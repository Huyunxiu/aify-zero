# 系统提示表面方案

> 中文副本。以 [`prompt-surface.md`](./prompt-surface.md) 为准。

会话以前根本不下发基线指令：`createSessionAgent` 把子 agent 目录拼在空串后面，模型读到的
第一行就是 `## Available Subagents`。怎么做事的规定散落在各条工具描述里，其中几条描述和
代码对不上。

这个方案把表面收成一个形状：一句身份、一段跨切面的规则，以及说真话的描述。

## 决策

| 决策              | 结论                                                                         |
| ----------------- | ---------------------------------------------------------------------------- |
| 身份              | 放进 base。主会话用 `MAIN_INSTRUCTIONS`，子 agent 保留自己的 preamble        |
| 跨切面规则        | 一个指令段，`priority: -20`，先讲怎么做事，再讲在哪做事                      |
| 子 agent 目录     | 从 base 挪成 `priority: 90` 的指令段；子 agent 不读它，它没有 `task` 工具    |
| 给子 agent 的文本 | 指令段上的 `renderForSubagent`；没有这个函数就读 `render`                    |
| 先读后写          | 只写成偏好，不做检查。会话级已读集合能被 `bash` 绕过，而且读过不等于内容没变 |
| 技能目录          | 不动。它约 4.7k token，参考实现付的是同一笔钱                                |
| 文案里的数字      | 由常量插值，常量和句子不会各说一套                                           |
| 验证              | 每条规则一条命名断言、块顺序、体积上限。假供应商测不了服从性                 |

## 规则管什么

这一段只收没有工具认领的规则：工具选择、先读再描述、编辑优先于重写、外部内容当数据、
写队列、路径确认、优先级、文件链接。工具自己能说清的，留在工具描述里。

## 被否决的选项

- **强制先读后写。** 最初提的是会话级已读集合。它看不见 `bash` 的写，而一次读也不证明
  内容还没变。规则只留偏好，真正的护栏是 `edit-file` 的匹配。
- **截断技能目录。** 参考实现大约在 500 字符处截断，本仓库已经在这个量级。再截会切掉
  路由依赖的触发词。
- **照搬参考实现的系统提示。** 它描述的是另一个运行时的工具集和它自己的输出格式。它是这份方案
  的检查清单，不是可以粘贴的来源。

## 与 issue 的偏差

- **补了三个术语，不是四个。** `instructions` 是系统提示的字段名，`System Prompt` 一个词
  就够；再加一个词会让同一个概念有两个名字。
- **`load-skill` 的死分支在本单里删掉了，没有另开 issue。** 删掉够不到的输入字段就必须改
  代码；把字段留在 schema 里，等于继续对模型说谎。
- **`task` 的描述不写任务和定时器的归属。** 那两句归各自的指令段，而且都给子 agent 另一份
  文本；写进 `task` 描述就是第二个权威。
- **子 agent 目录多了一条并行的规则。** 它本来就管委派规则，参考实现也说了这一条。
- **断言按规则写，不用一份 golden 快照。** golden 文件会让人盲更新；具名断言在规则消失时
  直接点名。

## 验证

`packages/agent/tests/prompt/surface.test.ts` 给每条规则一条具名断言，检查块顺序，并给固定
开销设上限。另有两条行为测试兜底：一批调用里只要有一条要问，整批都不跑；只读子 agent
拿到的工具集写不了盘。
