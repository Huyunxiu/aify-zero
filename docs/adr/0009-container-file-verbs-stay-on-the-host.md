# 容器适配器把命令放进容器，文件动词留在宿主

Apple 容器适配器只有一半的动词换环境：`exec` 走 `container exec`，跑在 Linux 容器里；
`readFile`、`writeFile`、`stat`、`readdir`、`mkdir`、`rm` 仍然直连宿主的 `node:fs`。

理由是两条约束同时成立：

1. 项目目录和会话目录按同一绝对路径挂进容器（ADR-0007），所以同一份路径在两边的字节
   完全相同。宿主读一份挂载里的文件，和容器里读同一路径，结果是同一个文件。
2. 每个文件动词走一次 `container exec`，代价是一百毫秒级的子进程往返；读一个几十行的
   文件也要付一次。文件工具是会话里调用最频繁的工具，这个代价会让整个会话变慢。

代价是一个刻意接受的不一致：**镜像自己的文件系统对文件工具不可见**。文件工具只看得见
挂载集，容器里的 `/usr`、`/etc`、镜像自带的 `node_modules` 要读就得用 `exec`（例如
`cat /etc/os-release`）。反过来，`exec` 的工作目录不受挂载集限制——在容器的 `/tmp` 里跑
命令是允许的，那里是容器自己的临时空间，命令跑完就没了。

## 越界判断

文件动词不再「读全部、只挡写」，而是读写都按挂载集校验，越界抛
`SandboxPathDeniedError`。这是容器适配器比原生隔离适配器多出来的能力：seatbelt 按
设计不限制读取（限制读会弄坏 `git push` 和 `ssh`），而容器里没有挂载的路径根本不存在，
挡住读取不需要额外的代价。

判断前先解析符号链接：工作区里放一个指向宿主其他地方的链接，不能让它把读写带到挂载集
外面。判断用挂载集的两种形态（原样与 `realpath` 之后），因为 macOS 的 `TMPDIR` 是
`/var/…`、真实路径是 `/private/var/…`，只留一种会把合法路径判成越界。

## Consequences

- 两个适配器的越界语义统一到 `SandboxPathDeniedError`，`SandboxWriteDeniedError` 这个名字
  不再准确（它现在也用于读取），随这次改动一并改名。
- 超时交给容器里的 `timeout -s TERM -k 5s`，不用外面那个 CLI 进程的截止时间：只杀
  `container exec` 的话，容器里的命令会继续跑，而工具已经告诉模型「超时了」。
- 取消只能停掉等待，容器里的命令可能跑到底。这一点比 `isolated` 弱——那边杀的就是命令
  自己的进程树。要靠镜像里的工具自己观察 `TERM`。
- 容器按会话建，`SandboxHandle.dispose` 删掉它。会话删除的流程还不存在，所以现在只在
  切换适配器时释放；在那之前，被放弃的会话会留着容器。
- 容器里的用户和宿主用户是不是同一个，取决于 CLI 与镜像；`exec` 写出来的文件在宿主的
  属主需要在一台装了 `container` 的机器上确认。文件工具不受影响，它们以宿主用户写。
