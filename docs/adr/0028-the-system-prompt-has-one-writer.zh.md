# 系统提示只有一个写入口

> 中文副本。以 [`0028-the-system-prompt-has-one-writer.md`](./0028-the-system-prompt-has-one-writer.md) 为准。

`turn_start` 和 `step_start` 补丁可以带 `instructions`，合并时整串替换。系统提示是回合开始时
由指令段拼出来的：环境、项目说明、技能目录、子 agent 目录、跨切面规则。返回
`instructions` 的插件会把它们全部删掉，每一步都这样，而且不说一声。`title.ts` 已经露出这条
缝：它读到补丁却丢掉 `instructions`，同一个 hook 在不同调用点行为不同。

一个字符串有两个写入口，这本身就是缺陷，不是少了一条规则。指令段已经能表达顺序、条件和
组合，子 agent 也能读到自己的那一份。补丁没有什么是指令段说不了的。

补丁现在只带一次调用当下需要的东西：模型。不在可补丁清单里的字段会被忽略，所以用
JavaScript 写的插件也碰不到系统提示。

## 考虑过的选项

- **保留替换，写进文档。** 犯一次错的代价是一份没有环境、没有项目说明的系统提示，而模型
  没法把这件事报出来。
- **只许追加的补丁。** 在指令段旁边再加一套追加机制，顺序问题要重新回答，测试也要再写一份。
- **一个写入口（选中）。** 指令段写系统提示，补丁改这一次调用。

## 后果

- 想改系统提示的插件注册一个指令段。它能给 id、优先级和子 agent 版本，这些补丁那条路从来
  没有过。
- `RuntimeSettings` 仍然保留 `instructions` 供请求使用，但 `RuntimeSettingsPatch` 不再有这个
  字段，合并时会过滤不认识的键。
- 原来证明“补丁不会留到下一回合”的那条测试，现在证明“补丁根本不会生效”。
