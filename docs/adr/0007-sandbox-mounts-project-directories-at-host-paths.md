# 沙箱挂载项目目录时使用宿主路径

沙箱里的项目目录挂在与宿主完全相同的绝对路径上：`projectDirs` 的每一项和
`sessionDir` 都原样可见，不复制一份进去，也不在沙箱里重新 clone。第一个非本机适配器
（原生隔离）继承这条约定。

理由：`primaryProjectDir` 是所有相对路径的基准。路径一致，模型看到的路径、`Environment`
提示、文件视图、改动视图和 git 基线就都不用改；复制或 clone 会立刻把「哪一份才是真的、
用户在外部改了文件什么时候可见、摘要算在哪一份上」变成新的设计问题。这一层第一阶段
只想要一条缝，不想顺手改掉工作区的定义。

## Considered Options

- **复制进沙箱**：隔离更彻底，但 UI 的文件视图与改动视图要改成读沙箱，基线算在谁身上
  要重新定义。
- **沙箱内 clone**：需要远端仓库，本地未提交的改动看不见，与「就地改用户项目」这个
  产品前提冲突。

## Consequences

文件不隔离：模型照样能写项目目录，能看见宿主上同一个文件系统。默认的 `host` 适配器
只隔离进程——它其实什么都不隔离；`isolated` 适配器另外约束命令与写动词（见 ADR-0008）。
要连读取一起隔离，得换成整个进程都在容器里的适配器（Docker 一类），那时这条 ADR 要
重新评估。
