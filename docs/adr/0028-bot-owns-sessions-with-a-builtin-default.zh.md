# 会话归属 Bot 且内置默认 Bot，项目保持正交可挂载

> 中文副本。以 `0028-bot-owns-sessions-with-a-builtin-default.md` 为准。

每条会话都归属于一个 Bot（`session.bot_id` 非空），系统内置一个不可删除的默认 Bot
（`id = "default"`），统一承接开箱会话与升级后的历史会话。项目保持正交可挂载的工作区概念：
Bot 可指定一个默认项目，每条会话创建时可挂载一个项目，或直接在 Bot 工作目录内工作。

我们将「会话级默认值」与「Bot 级实时能力」明确分开：

- **会话级字段**（选定模型与档位、审批策略、挂载的项目）在首次创建会话时从 Bot 复制默认值，
  之后归该会话独立持有。
- **Bot 级能力**（系统提示词、Skills、MCP 服务器、内置工具组、沙箱配置、环境变量和压缩策略覆盖）
  在每次运行时实时从 Bot 解析，因此修改 Bot 后在已有会话的下一个回合即可生效。

## 考虑过的选项

- **用 Bot 合并替代项目**：消除了共享项目抽象，导致多个 Bot 协作同一仓库时必须重复维护目录配置与
  git 基线归属。
- **允许 `session.bot_id` 为空**：会在 `buildSessionAgent`、工作区解析和会话创建界面里引入
  「有 Bot / 走老全局」两套并行分支。
- **Bot 仅作轻量级新建模板**：无法容纳跨会话工作目录、私有技能目录以及按 Bot 组织的会话历史。

## 后果

- `buildSessionAgent` 与 `resolveSessionWorkspace` 对所有会话只有一条统一装配路径，不再存在空 Bot 兜底分支。
- 历史会话迁移时自动归入 `default`，而默认 Bot 保持继承全局 Skills、全局 MCP 和全局 `AGENTS.md`，
  确保老用户行为不变。
- 删除自定义 Bot 时，若其下存在 `running` 或 `wait_review` 状态的会话则拒绝删除；通过校验后将其名下会话
  跟随软删除（ADR 0022），不强行并回 `default`。
