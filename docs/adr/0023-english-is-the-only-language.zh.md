# 只用英文

> 中文副本。以 [`0023-english-is-the-only-language.md`](./0023-english-is-the-only-language.md)@bcc56a0 为准。

仓库里的每段文字都是英文。每份文档旁边有一份中文副本。英文文件是权威。

## 形状

规则只住在 `docs/agents/language.md` 一个地方。`AGENTS.md` 只写一句指针。`commit-message.md` 管提交信息的格式，语言交给 `language.md`。

文档 `NAME.md` 有副本 `NAME.zh.md`。副本在标题下面写一行：
`> 中文副本。以 NAME.md@<sha> 为准。` 那个提交是英文文件的最后一次改动。副本指着旧的提交就
是过期，没有检查会因此失败；靠人读两份并补。

副本不是第二个真相。没有人手改 `.zh.md`。改动从英文文件起头，副本跟着走。

检查是 `vp run check:docs`。它读 `scripts/doc-pairs.manifest.json`，报五种缺陷：文档没有
副本、副本没有文档、清单里留着已经有副本的条目、清单里写着不存在的文档、清单里写着副本。
检查不读语言。

旧文档继续是中文，清单登记它们。登记过的文档在改到它的那次提交里变成英文：写英文版、把中文
原文移进副本、从清单删掉那一条。清单只会变短。

代码注释从这次提交起是英文。没人碰到的注释保持原样。会话里的回复仍是中文。

## 考虑过的选项

- **全中文**：提交的 type 与 scope 是英文词。subject 用中文，「祈使语气」与「开头小写」两条
  规则就描述不了任何东西。
- **接口类英文、判断类中文**：这是最初的决定，对英文弱的读者也更好。但它留下两套规则，而
  仓库只需要一套；在两者之间挑一个，正是按会话摆动的那件事。记在这里，作为落选的选项。
- **用 `.zh-CN.md` 而不是 `.zh.md`**：仓库已经有五份 `.zh.md`，没有一份 `.zh-CN.md`。`zh` 说
  的是语言；`zh-CN` 宣称了一个本仓库并不做的地域区分。文件名不是 locale 标签。
- **一次性翻完 46 篇中文文档**：这次提交会装着 46 篇译文和 46 份副本，没人读得下去。改用清单
  燃尽，每一步都还能评审。
- **两份都能改**：两个真相。`CODING_STANDARDS.md` 会在同一次提交里既新增 46 份文档，又破掉它
  自己「一个判断只有一个权威」的规则。
- **用 commitlint 规则加 CI 拒绝 header 里的中文**：读语言的机器会报假缺陷——subject 可能在
  反引号里引用一句中文文案。留下来的是那个错不了的检查：它只问文件在不在。
- **保留旧历史 / 改写旧历史**：13 条中文 subject 留着。改写远端历史换不来任何东西。

## 后果

- 读的人判断的是中文副本，权威却是英文文件。更正必须落进英文文件，否则这条决定否决掉的
  「两个真相」会一条一条长回来。`language.md` 里用一行写着这件事；这是本决定最薄弱的地方。
- 约 46 份中文文档会留在仓库里，直到有人改到它们。没人碰的文档可以好几年都是中文。
- 每改一份文档就多一次翻译成本。成本落在改文档的人身上，落在他最清楚内容的那一刻。
- `docs/` 的文件数翻倍。`grep` 与评审在一份文件的地方会看到两份。
- 提交信息的语言没有机器关卡。规则靠 `AGENTS.md` 指着它，靠人读结果。
