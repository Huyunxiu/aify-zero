# 子会话的记录是会话面板的一个视图

> 中文副本。以 `0035-a-subagent-record-is-a-view-of-the-session-panel.md` 为准。

子会话的记录原来是靠在会话旁边再挂一整个会话显示的。那一列生在会话路由里。ADR 0027
把会话从路由搬进外壳时，这一列跟着搬了过去，于是一种「怎么摆两份记录」的安排落进了
「拥有会话生命周期」的组件里。代价是具体的：最坏四列，先提交一帧上一个会话的子会话，
选择被刷新丢掉，分栏比例每次都重置。

现在这条记录是会话面板的一个视图，就在它出自的那份记录旁边：一个子会话一个标签，只读，
没有它自己的面板。子会话跑在父会话的 sandbox 里，再画一份文件、改动、终端就是把同一个
工作区画两遍。

选择记在会话地址上，是 `?subagent=<id>`。地址记的是选择，不是可见性：切标签不动它，
关掉那个标签才收回它。面板属于地址上有 id 的会话，所以会话列表那一屏——读者还没开始
一条会话时的入口——没有面板，也就什么都不选。

## 被否决的选项

- **保留并排的第二个会话**：整套会话都能复用，不必新写渲染器。代价是最坏四列，选择
  留在一个没有地址的模块级 store 里，两边都被钉在会重置的分栏比例上。
- **给它自己的路由**（`/sessions/<父>/agents/<子>`）：地址白拿，但读者读子会话时就
  看不见父会话，而父会话正是判断子会话还在不在干活的地方。
- **在会话内部再开一栏放只读记录**：父会话仍然看得见。它花掉面板本来就有的那一栏，
  而面板本来就用标签切换视图。

## 后果

- 记录只有一个渲染器。会话和子会话视图都画它，两处不会慢慢分叉。
- 需要一个会话 id 的视图不能从新标签页开出来：那一页能开的视图与视图类型分开列。
- 内容分派以一个穷尽检查收尾，加了视图却漏了分支就编译不过，而不是画成另一个视图。
- 会话永远是读者自己的那一份：第二列需要的那套只读形状已经删掉。
- 只读的记录不画回答入口：审批条和 fork 动作是不画，不是画出来却点不动。那一行仍然
  说明这次调用被卡住了。
- 记录是从一个地址上有 id 的会话来读的。会话列表那一屏没有面板，所以在那里点一次
  `task` 行什么也不开：那一屏正是旧的那一列能用、这个视图不能用的唯一一处。
