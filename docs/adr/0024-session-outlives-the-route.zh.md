# 会话活得比路由久

> 中文副本。以 `0024-session-outlives-the-route.md` 为准。

会话身上有地址重建不出来的活状态：一条打开的会话事件流、编辑框里的草稿、选中的
模型、滚动位置。这些都在会话组件里，而会话由路由渲染。任何替换掉它的路由都会卸载
它、断开连接、把草稿扔掉。设置随后也变成了路由，于是这种丢失就出现在读者正看着的
那一屏上。

现在会话住在 `_shell` 这个 pathless 布局里。布局下面的路由可以盖在会话上，而不是
替换它。要盖住会话的路由用 `staticData.coversSession` 声明这件事；外壳只问这一个
问题。于是 `/settings` 下面新加一节时，答案从它的布局路由继承，外壳不必认识任何
地址。

被盖住的会话照样在流。它只是不算读过：已读仍然要求文档可见且会话没被盖住
（ADR 0020），所以设置期间跑完的回合照样弹通知。

## Considered Options

- **把会话状态提到模块级的 store**：这样能活过任何导航，但重新挂载仍然会丢草稿、
  光标、终端尺寸和滚动位置，因为这些在 DOM 里。
- **把设置嵌成会话的子路由**：父路由不卸载组件，什么都不会丢。但设置的地址就跟着
  会话走，而且会话列表根本打不开设置。
- **把会话渲染在根路由的组件里**：同样能保活，但「哪些地址可以盖住会话」会变成一个
  组件里的一串路径判断，而那个组件并不认识这些地址。

## Consequences

- 外壳下面的路由不渲染会话。它们只带地址、参数和查询；会话由外壳渲染。
- 被盖住的会话对读者也不可操作：外壳给它 `inert`，上面的对话框接管焦点陷阱。
- 关闭设置走历史后退。直接在 `/settings` 进来的那次落在会话列表，因为没有可后退的
  条目。
