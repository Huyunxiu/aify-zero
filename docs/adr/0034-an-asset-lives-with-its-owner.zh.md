# 资源跟随所有者存放，经同一条字节路由对外提供

> 中文副本。以 `0034-an-asset-lives-with-its-owner.md` 为准。

应用要发给浏览器的文件，恰好属于一个所有者：一个 Bot 或一条会话。它存放在该所有者的目录下
（`<botHome>/assets/`、`<sessionDir>/assets/`），经一条字节路由
`GET /api/asset?owner=<kind>:<id>&name=<base>` 到达浏览器。这条路由先把所有者解析成一个根，再按
`/api/workspace/file` 早已验证过的方式发字节：无版本号 302 到 `?v=<mtime:size>`、`private, immutable`
缓存、`nosniff` 与 `CSP: sandbox` 策略。上传走 multipart 的 `POST /api/asset`，删除走
`DELETE /api/asset`；两者都只认所有者，不认识具体的 Bot。

归属是一条规则，不是一种目录布局。Bot 是一行数据，它的删除规则（保留或删除主目录）决定资源去留；
会话的文件树按需创建，行的软删除不会动它。没有任何东西集中收集，因此不需要垃圾回收、引用计数，
也不需要发明一个所有者列。

Bot 记录的头像是 `bot.avatar_path` 里的一个文件名，只在字节落盘之后由资产路由写入。客户端写不到它：
请求里的路径，就是读者可以指向任意位置的路径。

## 考虑过的选项

- **一个集中的 assets 目录加所有者列**：把归属、删除与访问检查在元数据里重建一遍，还要为“所有者
  已不存在”的行写一个收集器。
- **把本地 S3 兼容守护进程（MinIO）当 sidecar**：每种平台的二进制都要由 Forge 的 maker 带走，外加
  一个监听端口与一套凭据、AGPL 分发义务，以及一个不在桌面 server manager 生命周期里的第二进程。
- **经 RPC 层传 base64**：把二进制塞进 JSON，大小上限只能写在 schema 里而不是传输层，还会让一张
  2 MB 的图片和“改个 Bot 名字”共用同一次调用。
- **内容寻址命名**（`avatar-<sha256>.webp`）：把“删掉旧文件”换成“攒下孤儿文件”，又请回了这套决定
  本来要避开的收集器。

## 后果

- 新增一种所有者只多一条注册项（`root`，以及可选的后写钩子），三条路由一行不改。
- 除非所有者目录本来就是某个可读根，否则资产对 Bot 的工具不可见：Bot 的 `assets/` 不在沙箱挂载里。
- 一个基名只保留一份文件；换格式时删掉旧扩展名，而不是留下两份互相矛盾的文件。
- 会话资源比会话行活得更久，因为会话目录也是如此。这是软删除的既有欠账，资产层不假装没有它。
