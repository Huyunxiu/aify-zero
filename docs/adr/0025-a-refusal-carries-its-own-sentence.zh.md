# 拒绝自带那句话，会话把档位告诉模型

> 中文副本。以 [`0025-a-refusal-carries-its-own-sentence.md`](./0025-a-refusal-carries-its-own-sentence.md) 为准。

被策略拒绝的调用，过去只用一句常量回答模型："Tool call execution denied."。模型分不清这是拒绝、参数写错，还是工具坏了，于是换一个工具再试。`ToolStartDecision.reason` 一直存在，但没有人读它：执行层写常量，重建历史时又写一遍常量。

四条规则：

- **拒绝把交给模型的那句话写进记录。** `output-denied` 用 `errorText` 存它——同族的另外两个状态本来就用这个字段存「代替结果的那段文本」。重建时读这个字段，读不到就退到 `approval.reason`（这次改动之前写下的记录），再读不到才用常量。
- **重建是记录的纯函数。** 不按存下来的档位重新生成一句话，也不加时间戳。前缀缓存比的是字节，同一段历史第二次请求时说成另一句，从那里往后缓存全部作废。
- **`approval` 仍然是「问过、答了」的记录。** 策略、hook、宿主的拒绝没有审批，所以 `output-denied` 上的 `approval` 变成可选。硬填会伪造 `id` 和 `approvedAt`，而且 `approved: false` 会同时表示「用户拒绝」和「没有人被问」——这正是本功能守着的那条界线。
- **会话说清自己的档位拒绝什么。** `ApprovalPolicyExtension` 往提示里加一段，列出当前档位会拒绝的类别，以及遇到拒绝该怎么做。它问的是 `policyAnswer`，所以不拒绝任何东西的档位什么都不加。子会话重新渲染父的片段，不需要自己注册。

## 考虑过的选项

- **把策略做成 `pre_tool_call` hook**：规则只存在一处，但子会话不跑扩展的 hook，于是每个子代理和 fork 都能绕过它（ADR 0002）。
- **把被拒的工具从声明里藏起来**：模型就没得试。但声明是按注册静态决定的，这等于让工具目录随档位变化；提示加拒绝这两条已经回答了同一个问题。
- **把这句话塞进 `approval.reason`**：不用加字段，但它记录了一次没有发生的问答（见第三条规则）。

## 后果

- 被拒的调用显示一个带句子的 `REFUSED` 块，不再是一片空的 OUTPUT。
- 拒绝的措辞进入前缀缓存。中途换档会改变提示，下一次请求因此 miss 一次。
- hook 给出的理由现在能到模型；用户点拒绝时写的理由也能到。
