# 步骤视图拥有一个 part，而不是一层

> 中文副本。以 [`0026-a-step-view-owns-a-part-not-a-layer.md`](./0026-a-step-view-owns-a-part-not-a-layer.md) 为准。

一份会话记录里，一个工具的知识曾经散在三处：图标与标题在 `assistant-message.tsx`，高亮语言与 diff 在 `tool-panels.tsx`，摘要在 `tool-step.tsx`。第一处是一条 12 分支的链，其中 10 个分支逐字重复同一套行、`Frame` 与审批条。

上一次重构（AIFY0-108）把这三个文件按**层**切开：一行读什么、点开看什么、消息只做编排。这让每条规则只住一个文件，却让每个主体散在三个文件里。这次的决定保留层模块作为共享原语，把**步骤视图**立为权威：一个 part 一个模块，装下它的行说什么、正文画什么、摘要读什么。

四条规则：

- **一张表，键是 part 的 `type`，对协议完备。** 是 `Record` 不是 `Partial`，`dynamic-tool` 有自己的表项。协议新增一种 part，没有视图就编译不过。`custom` 与 `session.title` 的视图什么都不画：不画是一个决定，不是一次遗漏。分发仍然为表里不可能有的名字留一条路——会话记录是数据，不是类型：宿主工具的 part 是 `tool-<server>__<tool>`，另一个版本写下的回合带着那个版本的工具。这样的调用照旧读成一次调用，走同一个兜底视图；表叫不出名字、又不是调用的 part 什么都不画。
- **视图是组件，不是描述符。** `task` 画的那一行是选中旁边的面板，而不是打开弹窗；`questionnaire` 在自己的步骤之外再画一张表单。给这两者做数据记录，会长出回调，最后变成一个类型更差的组件。
- **壳拥有一行，视图拥有措辞。** `steps/shell.tsx` 画触发、行与审批条，`StepFrame` 是一次调用的卡片共用的外框。视图交出图标、标签、摘要与正文，只有上面那两处例外把整行拿回去。正文不是卡片外框的视图——笔记、重试、压缩标记——自己拼外框：给 `StepFrame` 加一个模式开关，读起来比第二套外框更难。
- **协议的读数留在原处。** `tool-step.tsx` 保留记录本身能回答的东西——状态、结局措辞、时长、回合的计数——因为那是对 part 形状的判断，不是对某一个工具的判断。依赖工具 `metadata` 的措辞住在那个工具的视图里。

## 考虑过的选项

- **描述符表**（图标、标题、摘要、正文都是数据）：整齐，也适合那些正文只有文字的 part。它不适合 `task` 与 `questionnaire`——它们的正文是不同的排布，不是不同的数据。
- **两张表**——工具一张、非工具一张：各自都很窄，但随后要有第三处决定读哪张。那第三处正是本决定要删掉的知识。
- **只搬 JSX、留下链**：消息里仍然有 12 个分支，主体仍然散在三个文件里。

## 后果

- 往 `AgentToolSet` 加一个工具，没有视图就编译不过。
- `tool-panels.tsx` 不再点名任何工具：读文件的语言与 edit 的 diff 搬到知道它们的视图，面板把语言当参数收。
- 需要环境状态的视图（`task` 与子会话面板）自己读，而不是由消息传进来。
- `assistant-message.tsx` 里的链变成一次查表。
