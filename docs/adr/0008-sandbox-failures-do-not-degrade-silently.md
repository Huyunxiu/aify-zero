# 沙箱起不来时不退回本机执行

适配器拿不到它要的环境时（容器没装、镜像拉不下来、平台的隔离手段不可用），装配直接
失败并报出原因，命令不会改在本机裸跑。默认的 `host` 适配器是用户明确选择的结果，不是
失败后的兜底。

理由：用户以为隔离了、其实命令在本机跑，比直接失败危险得多——那条命令能改到哪一个
文件、能删掉什么，用户没有任何办法预期。失败至少是可见的。

这条决定有具体实现约束：原生隔离适配器在 `acquire` 时真的起一个探针进程验证平台能
套上约束，而不是只看二进制在不在。`sandbox-exec` 在部分环境里存在、但 `sandbox_apply`
会被外层策略拒绝（本仓库的开发机上就是如此，退出码 71）；只看文件存在会让每一条命令
都以 `Operation not permitted` 失败，而用户无从判断这是策略没生效还是命令本身有问题。

## Consequences

- 选择沙箱适配器的方式必须是显式的（当前是 `AIFY_SANDBOX_ADAPTER`），且不认识的值要报错，
  不能退回默认值。
- 会话装配失败要让用户看到明确的原因，而不是一个「工具都不见了」的会话。
