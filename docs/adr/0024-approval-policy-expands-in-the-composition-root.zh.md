# 审批策略在组合根展开成决策，执行器不认识策略

> 中文副本。以 [`0024-approval-policy-expands-in-the-composition-root.md`](./0024-approval-policy-expands-in-the-composition-root.md) 为准。

会话有一个审批策略（编辑、只读、完全访问）。用户选择存在 `session.approval_policy`
里，每次运行都照它跑，不管这次运行是谁发起的。它在 `createSessionAgent` 里展开成
`ToolApprovalPattern`，与宿主规则（MCP 注解）折叠之后交给执行器；执行器和判定
层照旧只认 allow / ask / deny 三个答案。策略只有一处被读到：`ANSWERS` 表回答
「一个策略对一个类别给什么」。
执行器不认识策略。

策略回答按**审批类别**给出（读取、改动、命令、交互、未知），不按工具名。类别表
是内置工具的唯一清单，MCP 工具用服务器自己的注解；查不到注解就是未知，比按读取
放行安全。这张表同时取代了原来硬编码的 `DEFAULT_TOOL_APPROVAL_TOOLS`，所以
**内置工具**的询问集合只剩一处权威。MCP 工具的询问仍由宿主的
`createMcpToolApprovalPattern` 按注解回答：注解只有管理器查得到，合并进策略表就要
把管理器搬进 `approval-policy.ts`，那张纯函数表会从此依赖一个进程级单例。

五条不能改的规则：

- **拒绝最优先。** 任何一方说 `deny`，这次调用就不跑。理由跟着走：进模型读到的结果，也进记录，重建历史时才能说同一句（ADR 0025）。只有只读
  策略对改动类给 `deny`，它是封顶；宿主的放行翻不过它。未知类别（例如服务器开了
  `autoApprove` 的 MCP 工具）在只读策略下不表态：我们不知道它会写什么，就不假装
  知道。
- **宿主的具体放行优先于策略的「问」。** 宿主看过这次调用的入参（项目内写入、白名单
  路径），策略只按类别回答。拿具体换一般：会问的那一档不至于把宿主能放行的调用重新
  变回询问。今天没有哪一档对改动发问，所以这条先空着；折叠的顺序留着，等有档再问。
- **策略放松「问」，包括 hook 提的。** 用户选了一档，就是让这一类不再打扰他；那个
  「问」无论是宿主默认值还是 hook 提的，都由这一档关掉。完全访问因此是表里每一类的
  字面「不问」：带 `destructiveHint` 的 MCP 工具也不再问。留到最后的只有拒绝。
- **问卷谁也关不掉。** 问卷这类调用的内容就是问题本身：用户的答案是随审批一起回来的。
  一档策略放行它，不是让它少打扰人，而是把它弄坏——工具去审批里读答案，读到空，于是
  失败。所以 `interact` 没有格子，`policyAnswer` 在查表之前就把它答了。
- **子会话继承父的策略。** 子代理的行和 fork 出来的行都抄父/源的值。不抄的话
  它们会静默回到默认策略，父里放行的事换个会话又开始问。

## Considered Options

- **执行器里加一个 bypass 分支**：改动最小，但「能不能跑」就有了第二个判断处，
  和「一个判断只有一个权威」相悖；hook 与宿主规则也要各自再让一次路。
- **环境变量选策略**（`AIFY_SANDBOX_ADAPTER` 那种做法）：用户会中途改策略，环境
  变量改不了运行中的进程，也留不下会话级的记录。
- **每个工具一个布尔开关**（`autoApprove`）：组合数随工具增长，且回答不了「命令
  算不算改动」。
- **存进 `session.metadata`**：省一条迁移，但那列装的是不参与判定的东西；策略要
  参与判定，放进去等于每次使用都先把它打开。
- **策略做成第五个值 `auto`（让模型判断风险）**：判定是概率组件，它只应该放松
  「问」，不该成为策略表里的一行 —— 否则一张纯函数表要等一次网络调用。判定端口
  留给以后；计划是加第四个档，把每次调用交给判定，而表保持纯函数。

## Consequences

- 选择器少了一档，默认值变成 `edit`。库里存着 `standard` 的行一并搬过去，所以升级会让
  「从没选过」的会话少掉一次询问。
- 没有任何一层收紧策略。定时器或完成通知照用户选的那一档跑：这一档只回答「多常问」，
  上限由沙箱和只读档负责。所以完全访问下的定时器不问就改文件——那正是这一档的意思。
- `edit-file` 不再问，`bash` 除了只读以外仍然不问。要改这一点，需要单独一篇 ADR
  （那是一次影响所有人的手感变更）。
- 只读策略拒绝 `bash`：它是唯一新增的硬保护。读工具在任何策略都不多问一次。
- 历史运行仍然查不到当时用的是哪一档：那个值属于会话，不属于运行。要按运行追溯时，
  在 `run.start` 上补一个字段是加字段的增量改动。
