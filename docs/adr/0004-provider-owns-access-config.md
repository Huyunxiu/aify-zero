# 接入信息归供应商，模型只描述模型

模型记录不再持有 `apiUrl`、`apiKey` 和兼容类型。这些归供应商，模型只带自己的
模型 id 和能力。

理由：一家供应商的密钥和地址对它下面所有模型都一样。放在每条模型上，加五条
模型就要重复填五遍，改一次地址要改五处。多出来的副本还会互相不一致——库里的
`local.db` 就有两条 DeepSeek 记录，一条地址带 `/chat/completions`、一条不带。

代价：一次调用要两段配置，模型引用因此变成两个字段。会话、子 agent、事件里
凡是「用哪个模型」的地方都跟着改。

## Considered Options

- **模型持有全部字段（原状）**：设置页一张表最省事，但同一家的配置重复，且没有
  地方承载「这家用什么协议、发什么头」。
- **平级两张表，模型带 `providerId`**：设置形状更扁平，但删除供应商要级联删模型，
  还会留下指向不存在供应商的模型。
- **内嵌（选中）**：删供应商即删它的模型，不存在悬空引用；读取处拍平一次即可。

## Consequences

- 设置从 `models[]` 变成 `providers[].models[]`。旧数据在读取时按
  `(provider, apiUrl, apiKey)` 归并，不写数据库迁移。
- 模型引用是 `{ providerId, modelId }`，不是 `"provider/model"`。OpenRouter 的
  模型 id 自带 `/`，拼接有歧义。
- 协议从每条模型上移到每条供应商。一个供应商只能有一种协议；要用两种就配两条。
- 网关按引用解析供应商，运行中的补丁把模型换到别家时，地址和密钥跟着换。
- 密钥从「每条模型一份」变成「每家供应商一份」，副本减少，泄露面跟着减少。
