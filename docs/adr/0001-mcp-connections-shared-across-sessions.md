# MCP 连接由进程共享，不由会话持有

一个 MCP 服务器连接在 API 进程里只有一份，被所有会话复用。会话的 `McpExtension`
只向连接管理器要一份工具快照，不自己建连，也不在会话结束时断开。

这样做的原因：`buildSessionAgent` 每个回合都跑一次，连接若放在会话或回合里，每个
回合都会重启 MCP 子进程，既慢又会丢服务器侧的会话状态；而 MCP 服务器的常见用途
（工单、文档、数据库）本来就是跨会话的，不随会话生命周期变化。

代价：连接的生命周期不再和任何一次对话对齐。进程必须显式收掉子进程（`serve.ts`
的 shutdown），配置变更也要走「标记失效、下个回合重连」而不是直接断开。

## Considered Options

- **会话级连接**：隔离干净，但每回合重启一次子进程，冷启动落在第一次工具调用上。
- **回合级连接**：更糟，同一个问题。
- **进程级共享（选中）**：冷启动只发生一次，代价是要自己管进程回收和配置失效。

## Consequences

- 会话面板不显示连接状态，状态只属于进程，画在设置页。
- 子会话直接复用父会话的工具集，因此也复用同一份连接。
- 一个服务器挂掉只影响它自己的工具，不影响会话启动。
