# 发件箱走应用通道，回执才盖章

后台运行落定时，用户可能不在那个会话页上，甚至已经把窗口关进了托盘。今天应用内只有
一个会话级的未读位（`session.status = done`），而侧栏没有推送；应用外什么信号都没有。
这个决定加三样东西：会话级的发件箱记录、进程里的投递器、桌面主进程的通知与托盘。

投递走已经存在的应用通道 `/api/ws`。它的协议本来是 hello/world 的占位，就是留给这类
消息的；鉴权和 Origin 检查都已经在升级请求上做过了。

## 形状

行只指向回合，不存正文：

```
outbox_item(id, session_id, turn_id, created_at, delivered_at, expired_at)
  unique(session_id, turn_id)
```

正文要展示时回库读那一次的 step。存一份副本会在压缩、重命名、重生成之后和回合分叉，
而发件箱要回答的是「哪条回复到达了人」，不是「说了什么」。表按会话对齐收件箱：一条
运行只属于一个会话；「三个会话同时结束」是投递器的聚合问题，不是表的所有权问题。

生产的条件只有两条：结束状态是 `done`，且回合里至少有一段非空文本。失败、取消、等
审批都不算「有事要告诉人」；只有工具调用、没写回复的回合同样是「做完了但没话说」。
运行器只认一个「记一条」的端口，记录什么时候变成通知是投递器的事。

投递器每秒扫一次，取件的条件全写在一条查询里：未送达、未过期、会话仍是 `done`、到达
时刻已越过两秒的竞态余量、且不早于连接建立时刻。两秒不是产品上的静默窗口：运行先把
会话写成 `done` 才算落定，而正看着这个会话的页面要等收到 `run.end` 才标读，中间那段
`done` 说的是「刚跑完」而不是「没人看」。这不是延迟，是让最常见的误投不发生。

桌面主进程是唯一一条订阅发件箱的连接，因为能弹系统通知的只有它：窗口关掉之后渲染
进程就不在了，而那正是需要通知的时候。页面自己那条连接不订阅，所以同一台机器不会
两次打扰。

推送出去、通知弹出来，桌面才回执，服务端才写 `delivered_at`。`send()` 成功只证明字节
进了内核缓冲区；进程随后崩掉就记下了一条没发生的送达。每条只推一次：回执丢了就丢了，
重复弹一条比丢一行账更让人烦。同理，连接建立时不补发、进程重启时把没盖章的行全部标
过期——三小时前的结果现在弹出来是过时消息。

通道上只加三条消息：`outbox.subscribe`、`outbox.notify`、`outbox.ack`。载荷两端各自
校验，信封的严格解析不变。

## Considered Options

- **让投递器自己弹通知**：能弹通知的只有桌面进程。server 里常驻一个自己弹不出来的
  投递器，只是多一层管道，还多出一个只在「内置 server」模式成立的假设。
- **让渲染进程弹通知**：它已经有带凭据的通道连接，看起来最省。但 macOS 上 Cmd+W 会
  销毁窗口，渲染进程随之消失，通知恰好在该出现的时候没有了。
- **不靠推送，桌面每秒拉一个领取端点**：这能成立，而且少一个协议消息。但通道是现成
  的，拉取还要另开一个端点、另写一套原子领取；推送之后回执本来就是领取的另一种写法。
- **`send()` 成功即盖章，不要回执**：少一次往返，代价是 `delivered_at` 不再回答「弹了
  没有」，以后想做节流时手里没有可信的数据。
- **重启后补投**：用户会收到一串过时的通知，而且会话里本来就看得到。
- **模型显式请求投递（`send` 工具）**：回复本来就是回合。加一个工具会造出「回复了但
  没有投递」的第二真相，模型漏发时用户看到的是一次空运行。
- **同一会话在窗口内合并，或跨会话合并**：没有任何噪音证据。ADR 0014 已经因为同样的
  理由拒过一次静默窗口；操作系统自己会分组。

## Consequences

- `delivered_at` 由桌面写下，因此它只回答「弹了没有」。用户看没看见是另一件事，由
  `session.status` 的 `done → idle` 回答，两者不混用。
- 回执丢失的行在十分钟后转 `expired`，不会重推；一行最多打扰一次。
- 每行只推一次意味着内存里要记一份「推过」的名单。进程重启会清空它，但启动时把所有
  未盖章的行标过期，所以不会因此重推。
- 托盘成为「壳开着就算在线」的落点：Windows 和 Linux 上关窗不再退出，退出走托盘菜单。
  没有托盘时仍按老规矩退出。
- 主进程没有自己的语言设置：托盘菜单的文案跟界面语言走，渲染端把已经解析好的语言推
  过来，系统语言只在首屏加载之前兜底。
- 浏览器里没有通知：那条连接不订阅，也没有地方弹。Web 端只保留应用内的未读位。
- 通知的正文取回合最后一段文本，折成单行并截断到 120 字符；取最后一段而不是拼接全部，
  是因为一次运行可能先写过程、再写结论。
- 已送达和已过期的行保留三十天后由扫描删除。保留的意义是排障，不是归档。
- 「连接建立时刻」由通道自己记下，投递器每轮去问它。投递器要是等自己下一次扫描
  才记时刻，两次扫描之间落定的运行就成了「连接之前的历史」，永远不投。
- `GET /outbox/state` 是排障入口：上一次扫描的时刻、有没有连接在等、库里还等着几行。
  它只读，投不投仍旧只由那一条查询决定；`subscribed` 是 false 时结果再多也弹不出来。
- `wait_review` 不投递：等审批的会话确实该喊人，但那是另一条规则，等有证据再单独定。
