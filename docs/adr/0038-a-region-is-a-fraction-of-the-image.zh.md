# 区域是图片的一个比例

中文副本。以 `0038-a-region-is-a-fraction-of-the-image.md` 为准。

读图会把整张图压到像素与字节预算内。这是对的默认值，也是处理细节的错误工具：4K 截图缩到
1568 长边，12 px 的界面文字会变成 5 px 的糊块，模型看得出那里有个标签，读不出写的是什么。
裁剪是唯一保住分辨率的办法：同一张截图裁出四分之一，到达时就是原始像素。

读取接受一个可选的 `region`，四个数，每个都是图片的比例。裁剪的读取在源分辨率上完成，然后
同样的预算作用在剩下的部分上。

用比例而不用像素，是因为模型是照着已经看过的那份副本来画框的，而副本比源小。比例不需要换算
就能转移；源像素框要先乘倍数，乘错一次就裁错地方。换了文件、换了分辨率，比例仍然对。

信封同时报两个空间，因为两种坐标各有用处：比例用于再读一次，源像素里的边界框用于把在副本里
量到的坐标放回原图。

## 被否决的选项

- **源像素**：将来的点击工具会用这个单位。它强迫读者在每次裁剪之前先做乘法，还要假设这些
  数字指的是哪一张图。
- **上一次副本的显示像素**：与模型刚看到的一致。但读取是无状态的，它不知道上一次是哪一份。
- **比例**（本决定）：与分辨率无关，也与模型看过哪份副本无关。代价是信封里印一次乘法，而不是
  每个请求都算一次。
- **不做区域，只缩整图**：最简单。它让截图和密集文档不可读，而这正是这个功能存在的理由。

## 后果

- 这个参数只对图片有意义。文档忽略它；没有解码器的部署拒绝它，而不是读完整个文件、让模型
  以为自己裁过。
- 裁剪的读取存一个新对象：摘要不同，整图那份原封不动，两份都能再读。
- 裁剪后仍超出预算的图，照常被缩小，信封会说明哪个倍数把送出的副本映回区域内。
