# 提示词按挥发度排序

> 中文副本。以 [`0029-the-prompt-is-ordered-by-volatility.md`](./0029-the-prompt-is-ordered-by-volatility.md) 为准。

提示词是一个字符串，随每个步骤请求整份发出。前缀缓存比较的是字节：第一个不同的字节之后，
共享前缀就结束，后面每个 token 都要重新发送和预填充。提示词里有两个值自己会变——会话目录
每个会话变一次，日期每天变一次——而这两个值都排得很靠前：会话目录是环境段第二行，日期是
它的最后一行。于是每个新会话、每一天都在第二十行就分叉，规则、审批说明、项目说明、技能、
目录和工具目录从来没有被共享过。

规则是：自己会变的段排在其他所有段之后。环境段留下项目目录和机器事实；`This session` 段装
会话目录和日期，优先级 100，排在内建的子 agent 目录（90）之后。日期在段渲染时读，不在扩展
构造时读，所以跨过零点的会话在下一个回合说的是正确的那一天。

## 考虑过的选项

- **日期留在环境段。** 两个会变的值继续排在所有稳定内容前面，前缀是"设计上"就早早分叉。
- **整个环境段搬到末尾。** 多换来的只有项目目录，而它在同一个项目里并不变；代价是机器事实
  离使用它的工具很远。
- **日期放进用户消息。** 那消息前缀每一轮都变，而消息是请求里更大的那一半。
- **按挥发度排序（选中）。** 稳定的段在前，两个会变的值在最后。

## 后果

- 新会话或新的一天只重写最后一段，它前面的内容继续沿用供应商已经缓存的前缀。
- 宿主把段注册到 100 以上、或把环境段的优先级调到 100 以上，就会排在 `This session` 之后，
  前缀只稳定到那一段为止。优先级数字本身说明了这件事。
- 以后新增的段如果带着会自己变的值，应该放在这里，放在最后，而不是挨着环境段。
- 日期每个回合读一次，因为提示词每个回合渲染一次：变化在下一个回合生效，而同一个回合里的
  每一步读到的是同一份字节。
