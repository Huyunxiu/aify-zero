# 会话的最后活动写在回合边界

侧边栏的会话行要显示「3 分钟前」，列表要按它排序。这一列早就存在——
`session.updated_at`——但它只在插入时取默认值：开跑、收尾、改状态都不动它。
直接拿它当「最后活动」显示，一个三月建的会话今天用过，行上会写「8 个月前」，
而它偏偏还排在按 `created_at` 排序的列表中间。

这个决定给「最后活动」一个可执行的写入点：**回合开始时，回合结束时**。
`setActiveStream` 和 `clearActiveStream` 两条更新各写一次 `updatedAt`，别处不写。
旧行由一次数据迁移按回合补齐：取 `MAX(COALESCE(completed_at, created_at))`。
列表排序跟着从 `createdAt desc` 改成 `updatedAt desc`——时间列与顺序必须同源，
否则顶部是「2 天前」、底部是「3 分钟前」，读起来像缺陷。

## Considered Options

- **每次写 `session` 行都 bump**：改名、标记已读、状态切换一并刷新。最省心，但
  「活动」失去含义：改个名把会话顶到最前，标已读等于制造活动。时间列会随与内容
  无关的操作跳动，用户看到的是「它自己动了」。
- **不存列，读时从 `turn` 派生**：语义最准，永远和回合表一致。代价是每条列表查询
  都要带子查询取 `MAX`，分页的 keyset 与排序也要跨表；一个属性让热路径长期付费。
- **每个 `step` 写入都 bump**：回合内实时。但一个回合有几十个 step，写放大，而且
  step 是回合内部的事，不改变「最后活动」的粒度——粒度定在回合就够。
- **回合边界（选中）**：两个写入点，一句话能说清。排序键是 `(updatedAt, id)`——
  `updatedAt` 会重复，用 id 决胜；索引只建在 `updated_at` 上。

## Consequences

- 列表按 `updatedAt desc` 排序。游标因此不能再是会话 id：uuidv7 只保证按创建时刻
  有序，换成最后活动之后它不再同序。游标改成 `(updatedAt, id)` 的 keyset，由服务端
  返回 `nextCursor`，客户端不再从最后一行反推——它拼不出这个键。
- 索引换成 `(kind, updated_at)` 与 `(project_id, kind, updated_at)`。原来的
  `..._created` 两条没有别的使用者，同一条迁移里删掉。
- 标记已读、改名不动 `updatedAt`。打开一个会话不会把它顶到列表最前；改名也不会。
- 两个写入点带一个必填的 `recordActivity`，所以「这一笔算不算回合」由每个调用点
  当场表态，没有默认值可继承。开机恢复、`stop()` 清理残留标记、手动压缩、子会话
  清理都传 `false`：它们不是回合，一次启动不该把久未使用的会话顶到最前。
- 前端显示阶梯：一分钟内「刚刚」，一天内分钟与小时，之后按日历日——「昨天」指
  昨天那一格，不是「24 到 48 小时之间」；七天起改用日期。中文写 `11-09`，英文用
  `Intl` 的 `Nov 9`。所有行共用一个一分钟的时钟，只有时间那一个节点重渲染。
- 「最后活动」进入 `packages/server/GLOSSARY.md`。它是会话行的属性，避免的说法是
  「更新时间」「最后修改时间」——它们描述的是行被写入，不是会话被用过。
- 已知缺口：别的标签页里收尾的会话不会自动刷新。列表没有推送也没有轮询，行上的
  时间与状态都停在最后一次抓取。自己的会话在收尾时会失效一次列表，所以本页看到
  的读数是准的；跨标签页要准需要走会话事件通道，不在这个决定的范围。
