# 子代理验收

需要由人证明委派这套东西时，看这一页。自动套件覆盖的是零件：`subagent.e2e.ts` 从浏览器
驱动一次委派，`packages/agent/tests` 里两条缝覆盖工厂与通知。这一页覆盖没有任何自动用例
能到的地方：`Stop` 的两个答案、重启之后的恢复、以及模型自己的行为。

改动委派之前跑一遍。结果记在提出这个改动的那个 issue 里。

## 摆好现场

场景按固定的顺序回答，它不看你打了什么字，所以消息要按这一页给的顺序发。

**终端 1——替身：**

```bash
vp run fake:provider -- --scenario subagent-stop --port 4030
```

**终端 2——应用：**

```bash
vp dev
```

打开应用打印的登录链接，加一个供应商，baseURL 填 `http://127.0.0.1:4030/v1`（密钥随便
填，替身不校验），再把它列出的模型加进来：`fake-fast`。

重启替身，场景就从头再走一遍。下面两遍之间要重启一次。

如果重启 API 的时候还有子代理在跑，启动收尾会自己开一轮。等这一轮结束，再重启替身：
这一轮走的是同一个供应商，会把场景的规则吃掉，下一条请求就会报 `the scenario ran out of
rules`。

## 第一遍——链条，以及 `Stop` 的两个答案

### 1. 派活的那次调用先返回

发这一句：

> Start a subagent that finds the router

看什么算对：出现 `Subagent` 行；回合停在 `Started AGENT-1. It will report when it is
done.`；报告原文还不在页面上。子代理要等 25 秒才开口，够做下一步。

### 2. 停止会把子代理一起带走，并且不为它说什么

子代理还在跑的时候按 `Stop`。

看什么算对：子代理那一行变成 `canceled`，父会话的回合跟着取消。再发一条消息，会话记录
不该以一条「停止了」的通知开头——这次停止是你要求的，报告它只是噪音。

### 3. 停止也可以把子代理留下

重启替身，开一个新会话，还是发那一句。子代理还在跑的时候，打开 `Stop` 右边的菜单，选
**只停本轮，子代理继续运行**。

看什么算对：父回合结束；子代理继续跑。大约 25 秒后它落定，而**屏幕上什么也不会发生**
——通知在等。随便发一条消息：通知出现在那条消息的答案之前，父会话先读到报告，再读你的
新话。

### 4. 崩溃会被报告给父会话

重启替身，开一个新会话，还是发那一句，然后在子代理还在跑的时候杀掉终端 2 里的 API 进程，
再启动它。

看什么算对：几秒内会话自己醒来，出现一个 `Subagent finished` 的块，带着终态，并且有一个
回合回答它。这就是恢复那条路：新进程把子代理那次运行收尾了，而通知自带让会话能起跑的载荷。

## 第二遍——提示词

把会话切到真供应商，停掉替身。重复一次委派，然后按名字跟子代理说话。

看什么算对：

- 模型派生一个子代理，然后结束它的回合。它不会在同一轮里去轮询 `list-agents`。
- 名字抄得一字不差，而且只用名字就够到它。
- 让它给子代理递话时，它的回答会说这句话现在生效，还是等下一步边界。
- 通知到了以后，模型用的是通知里带的报告，不会再去调 `list-agents` 或 `send-message`
  取一遍。

每条用一句话写下来你看到什么。第二遍不可能确定性地失败：它测的是模型。
