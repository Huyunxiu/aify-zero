# Database

表结构以及它的版本历史：一个 SQLite 库文件怎么从空文件长到当前结构，以及一个
已经存在的库怎么追上代码。

## Language

**迁移 (Migration)**:
一条已提交的 SQL 单元，把一个库从上一个结构版本带到下一个版本。
_Avoid_: 数据库变更、变更集、数据库脚本

**迁移文件 (Migration File)**:
仓库里承载迁移的文件，包括它的 SQL 和对应的结构快照。它是表结构的唯一来源。
_Avoid_: 补丁、schema 脚本、SQL 文件

**迁移历史 (Migration History)**:
某个库已经应用过哪些迁移的记录。它随库文件一起保存，所以同一个文件被搬走时
历史也跟着走。
_Avoid_: 版本号、迁移日志、迁移进度

**基线 (Baseline)**:
把一个已经建好表的库一次性标记为「迁移全部已应用」，不重放任何 SQL。它只用于
迁移历史为空的库。
_Avoid_: 初始化、重置、同步

**结构漂移 (Schema Drift)**:
表结构已经改动、但迁移文件还没跟上的状态。表现出来是启动迁移无事可做，而代码
读的列并不存在。
_Avoid_: 结构不一致、版本落后、schema 不同步

**开发库 (Development Database)**:
一个 checkout 自己的库文件，就是根部的 `local.db`。它不跟着分支走，也不在
worktree 之间共享。
_Avoid_: 本地库、测试库

**用户库 (User Database)**:
打包后的应用自己拥有的库，位于用户目录。它跟着应用版本向前迁移，不被人直接
编辑。
_Avoid_: 生产库、正式库、线上库
