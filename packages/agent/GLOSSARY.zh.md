# Agent

> 中文副本。以 [`GLOSSARY.md`](./GLOSSARY.md) 为准。

一个会话的助理：模型循环。一个会话由若干回合组成，一个回合由若干步组成，一次运行驱动
其中一个 assistant 回合。工具、钩子和指令段在装配时进入这个循环。

## Language

**助理 (Assistant)**：
一个会话对话的那个 agent：模型循环，连同它能用的工具、技能、子代理和定时器。代码里叫
`Agent`，表里叫 `agents`；对用户说的词是助理。这个词也指一个回合的角色——assistant 回合装
回答——那个回合不是助理。
_Avoid_：助手、智能体、机器人

**子代理 (Subagent)**：
一个会话为了办一件事而启动的助理。它有自己的会话与会话记录、自己的工具，以及在启动时委派
会话所持的审批策略。它不能再启子代理，也不能问用户任何事。它向启动它的那个助理汇报，那个
助理在它汇报之后还能再给它消息。
_Avoid_：子 agent、子代理进程、worker、后台代理

**子代理名 (Subagent Name)**：
一个会话用来找到自己某个子代理的句柄。它在该会话的子代理之间唯一，且不改变。两个会话可以
各有一个同名的子代理。
_Avoid_：id、句柄、别名

**回合 (Turn)**:
会话里按顺序排列的一段交换。user 回合装一条输入，assistant 回合装对它的回答；一次运行可以
产生多个 user 回合和一条 assistant 回合。
_Avoid_: 轮、对话轮、用户回合

**会话记录 (Transcript)**:
一个会话里按顺序落定的全部回合；子代理的记录就是它自己那条会话的记录。待审批住在它里面；
压缩往它里面追加标记与摘要，被盖住的回合原文仍在——改的是模型侧历史，不是记录。
_Avoid_: 转录、对话记录、历史

**运行 (Run)**:
一次从起跑到结束的模型执行，用一个运行 id 标识：它在起点领取收件箱里的全部待办项，
让它们成为 user 回合，再驱动挂在最后一条之后的那条 assistant 回合，并把它自己的载荷
写回会话——下一个进程没有这份记忆，而推迟的待办项仍要唤醒这个会话。事件流、领取和
暂停都以它为界。
_Avoid_: 任务、会话、流

**收件箱 (Inbox)**:
一个会话里按到达顺序排列、还没进入循环的东西。用户消息、定时器到点、外部事件都
写进这里；一次运行开始时从它领取。
_Avoid_: 待发箱、发送队列

**待办项 (Inbox Item)**:
收件箱里的一行，记着内容、到达顺序，以及最早能在哪个边界交进去：本次运行中途，还是
下一条运行。一次运行可以领走多条：每条仍是一个独立的 user 回合，回复只有一条，挂在
最后一条之后。
_Avoid_: 消息、事件、任务、合并

**载荷 (Payload)**:
一次运行起跑所需的配置：模型、effort，以及它所在的项目。待办项自带一份，因为起跑
的就是它。会话记住最近用过的那一份，因为推迟的待办项可能要唤醒的会话，这个进程一次
都没跑过。
_Avoid_: 模型配置、参数、配置

**发件箱 (Outbox)**:
一个会话里已经落定、还没送到人的回复记录。它是收件箱的反面：那边是进来的东西，
这边是出去的东西。一次运行落定成 `done` 且确实说了话，就留一条；没话说、失败、
取消、等审批都不留。
_Avoid_: 发送队列、通知列表

**发件项 (Outbox Item)**:
发件箱里的一行，指向一个已落定的回合。它不存正文：正文在回合的 step 里，复制一份
会随压缩和重生成分叉。送达之后留下做账，没有送达的在过期之后留下做账。
_Avoid_: 消息、通知、提醒、推送

**投递 (Delivery)**:
把发件项变成一次系统通知。以通知已经显示为准，不以用户看见为准；它和「交付」不是
一回事——交付是把待办项交进模型循环（入站），投递是把发件项送到人（出站）。
_Avoid_: 发送、推送、通知

**投递器 (Outbox Dispatcher)**:
进程里那个扫描循环：挑出到条件的发件项，推给在等的桌面连接，收回执。它不弹通知，
也不决定用户有没有看见；推送出去的行不会推第二次。
_Avoid_: 调度器、发送器、worker

**后台任务 (Job)**:
模型发起、比一次请求活得久的命令或工作。注册表记账它的身份、归属、生命周期和
输出；执行资源归生产方。「任务」在散文里是它的简称，但不能用来指一次运行。
_Avoid_: 作业、job（中文行文）、后台进程

**完成通知 (Completion Notice)**:
后台工作结算后投给拥有者的一条消息。生产者是后台任务或子代理。它不是用户输入，也不结束
运行。
_Avoid_: 完成消息、回调、完成事件

**定时器 (Timer)**:
会话上一个有「下一次触发时刻」的对象。到点后它往收件箱写一条待办项，会话因此可能
被唤醒；它自己不跑模型，也不属于某次运行。两种：跟进与日程。
_Avoid_: 提醒、闹钟、定时任务、cron

**跟进 (Follow-up)**:
只触发一次的定时器。触发之后它就不存在了；到点那次运行用的是设定它时的模型。
_Avoid_: 提醒、一次性任务、超时

**日程 (Schedule)**:
按周期重复的定时器。触发之后把到期时刻推进到下一次，直到被撤销。它带一条周期规则；
日历规则还带一个写定时固化的时区。
_Avoid_: 定时任务、周期任务、循环任务、cron

**周期规则 (Recurrence Rule)**:
日程重复的节拍：每天、每周的某几天，或固定间隔。前两种按当地墙上时间算，后一种按
绝对毫秒算。
_Avoid_: cron 表达式、RRULE、重复规则

**插话 (Steering)**:
运行中人或者另一个代理补的一句话。它作为一条引导消息，在下一个步边界进入当前回合，不拆成
独立的 user 回合。
_Avoid_: steer、中途消息

**会话事件流 (Session Event Stream)**:
一个会话的事件通道：把连续几次运行接成一条给读者看的序列，每次运行自成一段
（`run.start` 到 `run.end`），运行之间的空档不关闭它。读者按会话游标往后读，
所以排队中的待办项被领走时，读者已经在看了。
_Avoid_: 数据流、事件流（一次运行的）

**工具 (Tool)**:
模型可以请求执行的一个动作，由名字、说明和入参结构描述。内置工具和 MCP 工具
都是工具，区别只在来源。
_Avoid_: 函数、函数调用、能力

**MCP 服务器 (MCP Server)**:
按 MCP 协议对外提供工具的一个独立进程或 HTTP 服务。
_Avoid_: 插件、集成、连接器、外部服务

**MCP 工具 (MCP Tool)**:
属于某个 MCP 服务器的工具。它和内置工具在会话里地位相同，但可用性取决于那个
服务器是否连得上。
_Avoid_: 远程工具、外部工具、第三方工具

**暴露方式 (Exposure)**:
一个工具是随每一步请求声明给模型，还是只在工具目录里等模型来搜。
_Avoid_: 可见性、模式、mode、懒加载

**工具目录 (Tool Catalog)**:
模型当前看不见、但可以搜到的那批工具。它不是一个新来源，只是工具被藏起来的部分。
_Avoid_: 注册表、索引、工具箱

**转调 (Route)**:
模型说出工具的准确名字和入参，由内核找到那个工具并执行，模型没有直接调用它。
_Avoid_: 代理、包装、网关、gateway

**授权 (Authorization)**:
用户在一台 MCP 服务器上同意之后，客户端取得该服务器访问凭据的流程。发起者是用
户，客户端不代替用户同意。
_Avoid_: 鉴权、登录、认证

**授权令牌 (Authorization Token)**:
授权之后客户端持有、随每次请求发给 MCP 服务器的凭据。它和本地 API 的访问令牌
不是一回事：前者属于第三方服务器，后者只证明请求来自本机客户端。
_Avoid_: 密钥、apiKey

**扩展 (Extension)**:
在会话装配时注册工具、钩子或指令段的一段代码。一个扩展可以注册多个工具；
一个 MCP 服务器不是扩展。
_Avoid_: 插件、模块、集成

**系统提示 (System Prompt)**:
每个步骤请求里作为模型指令发出的那段文本。它以身份句开头：主会话读 `MAIN_INSTRUCTIONS`，
子 agent 读它自己的 preamble；每个指令段再按优先级贡献自己那一段。别的代码不写它：起始补丁改的是
这一次调用，不是提示。代码里的字段名是 `instructions`。
_Avoid_: 提示词、提示片段、系统消息

**指令段 (Instructions Section)**:
扩展在装配时贡献进系统提示的一段文字。它有一个 id、一个优先级和一个渲染函数；数值越小越先渲染。
函数只返回这一段自己的文字，别的什么都不管：分隔由写入口拼，指令段自己不写。指令段归注册它
的扩展。当一段话对子 agent 不成立时，它可以用 `renderForSubagent` 给子 agent 另一份文本；
空串表示子 agent 根本不读这一段。
_Avoid_: 提示片段、prompt fragment

**技能 (Skill)**:
存在技能目录里、以 `SKILL.md` 形式出现的一套指令，由会话用 `load-skill` 工具按需加载。
系统提示只列出可用技能的描述；正文只有在模型加载时才进入对话。
_Avoid_: 提示模板、prompt template、插件

**重试 (Retry)**:
一步失败之后，在同一个回合里用同一份历史重新请求一次。它本身是一步。次数
只在重试上算：第一次请求不算，之后每一次重新请求都算一次重试。
_Avoid_: 重发、再试、重新生成、尝试

**运行器 (Runner)**:
一个会话的常驻推进者：从收件箱领取待办项、起跑、在失败或中止后暂停，持有唯一的运行锁，并负责会话的 create / resume / stop / compact / fork。主会话的运行只由它开始。
_Avoid_: 调度器、worker、后台服务、运行时

**暂停 (Paused)**:
运行器不再自动开始下一次运行的状态。它是对自动推进的刹车，不是对会话的关闭。
_Avoid_: 停止、中断、挂起

**审批策略 (Approval Policy)**:
一个会话对工具调用的询问姿态：哪些直接放行、哪些必须问、哪些不许做。它只决定
问不问；能不能做归沙箱。用户选的策略存在会话上，运行时按场收紧。
_Avoid_: 权限模式、permissionMode、授权、策略模式

**审批类别 (Approval Class)**:
一个工具在审批上的分类：读取、改动、命令、交互、未知。策略按类别回答，不按
工具名；MCP 工具的类别来自服务器自己的注解，查不到就是未知。
_Avoid_: 风险等级、权限级别、工具类型

**Attachment (附件)**:
一次读取记录下来的字节。会话记录会重放它的读取，所以附件永不改变：标识它的是字节的摘要，
而不是名字。它不是资源：资源是 owner 按名字替换的可变文件。
_Avoid_: 资源、上传、文件、blob

**Content (内容)**:
一次读取的结果，有三种形态：文件的文本、目录的条目、或一个附件。形态由路径决定，模型不选。
_Avoid_: 正文、数据、结果

**Input Kind (输入种类)**:
模型路线声明自己能接受的一种媒体种类，按设置 schema 的写法：text、image、audio、video、pdf。
什么都没声明的模型路线只接受 text，所以未知的模型路线永远收不到图片。
_Avoid_: 模态、能力、modality

**Normalized Copy (规范化副本)**:
图像附件的存储形态：单帧、8-bit、sRGB、无元数据，落在固定的像素与字节预算内。读取存下的
就是它；源文件留在原处，引用记下原始尺寸，读者据此把坐标换回去。
_Avoid_: 缩略图、缓存图、派生图

**模型路线 (Model Route)**:
一次模型调用的去向，用请求装配需要的两件事表示：供应商接受的协议，和模型读的媒体种类。
每一步读一次，因为补丁可以把会话换到另一个模型。它不是本文件的「转调」：转调改变的是工具
调用的去向。
_Avoid_: 模型配置、供应商、通道

**Region (区域)**:
一次读取保留的图片范围，用四个比例表示宽与高的份额。没有区域的读取保留整张图；有区域的读取
在其中按源分辨率工作。
_Avoid_: 裁剪框、crop、视口

**Crop Box (裁剪框)**:
与 `Region` 指同一个范围的源像素版本：方向应用后盒子从哪里开始、多大。区域是调用方要的，裁剪框
是读取真正做的。
_Avoid_: 矩形、rect、bounding box
